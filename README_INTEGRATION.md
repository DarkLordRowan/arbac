## ВАЖНАЯ научная оговорка

У существующего `arbacc/accelerators/levin_sidi_s.py` в docstring прямо написано, что реализация соответствует **факториальному преобразованию семейства Weniger**, а название исторически взято из C++ библиотеки. Не следует выдавать её за независимую реализацию полного S-преобразования Сиди без проверки формулы по первоисточнику. Oracle проверяет *именно реализованную* формулу. Наш тест на численную эквивалентность `weniger` тоже НЕ делает эту формулу независимой от Weniger.

Такую номенклатуру нужно окончательно уточнить до статьи; архив исходников не содержал логи Stage C/E и их полные JSON/Parquet, поэтому полное численное воспроизведение итоговой таблицы тезисов не проверено.

## Windows: как проверять

1. Распаковать ZIP в **новую** папку `ArbacIntegrated`, не поверх старой `arbac-Magister` и не поверх `Arbacv2`.
2. В PowerShell:

```powershell
cd C:\Users\DLR_ACER\Desktop\ArbacIntegrated
python -m pip install -r requirements.txt
python -m pip install -r requirements-research.txt
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\VERIFY_LOCAL_INTEGRATION.ps1 -Workers 8
```

После успешной проверки:

```powershell
python -m arbac_research gui .\out\research_smoke_v3_profiled
```

**Не заполняйте исходные `out` папки смешанными экспериментами из разных версий**. Parquet-запись по протоколу v3 должна иметь новую директорию; `analyze` может читать старые данные.

## Сохранение в Git

Действующие ветки `main` и `Magister` в GitHub здесь **не изменялись**. Архив не содержит `.git`.

После проверки Windows предлагаем перенести файлы в отдельную рабочую ветку Git **из существующего Git-клона**, вначале сохранить локальные некоммиченные изменения, и проверить:

```powershell
git status --short
git diff --check
git diff --stat
python -m pytest tests research_tests --ignore=tests/gui -q
```

Затем оформить коммиты отдельно для (1) алгоритмов и oracle, (2) Parquet/GUI/metrics. Не коммитить результаты `out`, временные данные и `__pycache__`.

## Границы реализации

Исследовательский runner сейчас поддерживает **задачи акселерации**, но **не переносит автоматически postprocess/envelopes** из обычного Arbac. Для них используется прежний CLI. Строковые значения высокой точности сохраняются в Parquet; `float64` используется только для графика/приближённого просмотра, не для расчёта математических метрик.
