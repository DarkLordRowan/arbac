# Продолжение: источники с особой математической семантикой

В `Magister` перенесены последние 11 источников каталога C++: семь последовательностей
Румпа, натуральный ряд, квадратура и два быстро сходящихся ряда. Теперь в Python
110 синтетических источников, файловый источник и 11 ускорителей; все 109 позиций
каталога C++ имеют аналоги с независимыми проверками. Это не означает, что каждый
источник является сходящимся рядом. Остаются 12 семейств алгоритмов C++.

## Последовательности

`SequenceBase` хранит непосредственно s_n. Ускорители и график используют эти
значения без повторного суммирования; оценки остатков получают разности при
необходимости. Шум применяется к самим значениям последовательности. Отдельный
тест с числами порядка 1e150 проверяет отсутствие потери малых значений при
ненужном вычитании и восстановлении последовательности.

У Румпа есть два режима: `evaluation="backend"` воспроизводит округление и порядок
операций исходной формулы; `evaluation="exact"` вычисляет рациональные значения
через Fraction и округляет только выдаваемые точки. Точные значения проверяются
независимой линейной рекурсией y_n, где u_n=y_(n+1)/y_n.

В точной арифметике №1 и №2 имеют u_6=0 и не определены с индекса 7; №4 имеет
u_16=0 и не определена с индекса 17. Поэтому для них нет прежних «эталонных сумм».
Для невозмущённых №3, №5, №6, №7 пределы соответственно 6, 5, 36 и
(-61-sqrt(3657))/4. При ненулевом возмущении x автоматический эталон отсутствует.
В режиме backend уход №5 к 100 при малой точности сохраняется как исследуемый
эффект; это отдельно проверяется тестом. Исправлена также двойная константа
61.0/11.0 в C++: деление теперь выполняется в целевом типе.

Литература: [Rump, ETNA 52, 358–369](https://doi.org/10.1553/etna_vol52s358),
[дополнение, 571–575](https://etna.ricam.oeaw.ac.at/vol.52.2020/pp571-575.dir/pp571-575.pdf).

## Остальные источники

`natural_series`: обычная сумма 0+1+2+… расходится. Значение -1/12 доступно отдельным
методом регуляризации и не используется для ошибки ускорения относительно суммы.
См. [DLMF 25.6](https://dlmf.nist.gov/25.6).

`integral1`: исправлена квадратура интеграла log(t)/(1+t) на [0,1]. Подстановка t=u²
даёт непрерывный интегранд 4u log(u)/(1+u²), равный нулю на обоих концах.
Все панели учитываются. Последовательность с индексом n использует steps*(n+1)
панелей; предел -pi²/12. Ограничение max_panels предотвращает случайные чрезмерные
вычисления. Проверяются сетки, все трапеции, предел и ограничения параметров.
См. [интегральные представления eta, DLMF 25.2](https://dlmf.nist.gov/25.2).

Для Σ(-1)^k k!/k^k и Σ(-1)^k/k^k вместо восьмизначных констант вычисляются
знакочередующиеся суммы с оценкой остатка первым отброшенным членом. Arb включает
эту оценку в радиус; для mpmath это вычисленная высокоточная оценка. Масштаб x
сохранён. В C++ учтено, что native float precision=0 обозначает встроенную точность.

Независимые эталоны получены квадратурами:

- Σ(-1)^k k!/k^k = ∫₀¹ log(t)/(1-t log(t))² dt;
- Σ(-1)^k/k^k = -∫₀¹ t^t dt.

Их можно вывести из [интеграла Эйлера, DLMF 5.9](https://dlmf.nist.gov/5.9)
и [геометрического ряда, DLMF 4.6](https://dlmf.nist.gov/4.6).

## Интеграция и проверка

Сохранение result.json включает `exact_sum`, `source_kind`, `reference_kind`;
загрузчик поддерживает прежние файлы без exact_sum. Ошибка материализации источника
возвращает статус failed с доступной историей ускорителя. Проверены исполнение,
сохранение, шум и подготовка данных графика без GUI-зависимостей.

Полный прогон: **1957 passed**, mpmath и Arb. Шесть прежних предупреждений связаны
с multiprocessing fork; GUI-тесты исключены. Проверены все новые источники с
компилируемым C++ catalogue_probe, а также прежние межъязыковые проверки.
CTest: **1/1**. В C++ добавлены проверки семантики последовательностей, квадратуры,
отсутствующих сумм и точности двух эталонов при 200 битах MPFR.

Воспроизведение — команда из mathematical-verification.md с переменными
SHANKS_CPP_REGRESSIONS и SHANKS_CPP_CATALOGUE. Выборочная таблица catalogue-sample.json
остаётся диагностикой конечных double-траекторий, а не доказательством сходимости.

Основной C++ target `shanks` полностью собран после исправлений. Математические
регрессии также проходят с AddressSanitizer и UndefinedBehaviorSanitizer.
`git diff --check` чист в обоих репозиториях. Работа сохранена в локальных ветках
`Magister`; коммиты и push не выполнялись.
