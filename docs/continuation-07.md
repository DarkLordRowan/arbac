# Продолжение: Anderson и две исторические реализации Ford–Sidi

В `Magister` добавлены Python-методы `anderson`, `ford_sidi`,
`aitken_backtracking`; теперь зарегистрированы 20 ускорителей.
Остаются три семейства C++: Chang–Wynn, J, Wynn epsilon 3, а также отдельные
варианты уже перенесённых семейств. Все 109 источников каталога остаются покрыты.

## Anderson

Источник: [Walker–Ni (2011), §§1, 4](https://doi.org/10.1137/10078356X).
Реализована скалярная Type-II схема на наблюдённых парах
`(x_i,g_i)=(s_i,s_(i+1))`. Это преобразователь готовой последовательности:
он не вычисляет функцию g и не возвращает ускоренную точку в итерационный процесс.

Невязки равны f_i=g_i-x_i, столбцы F — разности соседних невязок.
Решается min ||f_current-F*gamma||² + lambda*||gamma||².
При lambda=0 выбирается решение с минимальной нормой коэффициентов; при нулевом
ранге берётся gamma=0. Новая точка вычисляется через разности x и f с демпфированием.
Для скалярной невязки решение выражается через сумму квадратов, без формирования
вырожденной матрицы нормальных уравнений. В комплексном C++ используются сопряжения.

Исправления старого C++: повторяющиеся строки матрицы истории, абсолютная величина
вместо знакового знаменателя Эйткена, неверная обработка вырожденного решения.
**Изменение параметров:** safeguard теперь означает ridge-параметр lambda>=0,
а не порог знаменателя. В Python он называется `regularization`. По умолчанию
lambda=1e-12 и memory=50. beta конечен и принадлежит (0,1]; память положительная.
Некорректные значения отвергаются, а не молча заменяются единицей.
Без истории используется демпфированная исходная пара; первый элемент возвращается
как есть. Сходиться к известному пределу при произвольных данных метод не обязан.

## Ford–Sidi

Источники: [Ford–Sidi (1987)](https://doi.org/10.1137/0724080),
[описание рекурсивного исключения у Sidi (1990), §1](https://www.digizeitschriften.de/download/pdf/362160546_0057/log28.pdf).

`ford_sidi_3_algorithm` раньше заполнял только одну строку начальных данных,
использовал остальные нули, игнорировал order и обращался к данным до проверки
размеров. Вместо этой некорректной реализации введено рекурсивное исключение
Ford–Sidi для явно заданного базиса ошибки
`omega_i*(beta+i)^(-r), r=0..k-1`. В Python это `ford_sidi`.
Модель совпадает с моделью Левина, но способ вычисления другой. Все обобщения
W^(m) этим методом не реализуются. Для больших порядков исключение может
требовать больше рабочих знаков, чем прямая взвешенная формула.

**Изменение интерфейса C++:** n теперь начало окна, order=k учитывается;
нужно k+1 сумм плюс данные для оценки остатка. При k=0 возвращается s_n без an.
В конструкторе можно задать тип остатка и beta>0. Поддержаны next/t/u/v/v_shift.
Python по умолчанию использует next, C++ сохраняет прежний u; при сравнении
вариант задаётся явно.

`ford_sidi_2_algorithm` фактически является Эйткеном с поиском предыдущего
невырожденного окна. Историческое имя C++ сохранено; Python использует
`aitken_backtracking`. Исправлены размер n+3, допустимость n=0, включение
нулевого окна в поиск и сброс знаменателя между проверяемыми окнами.
Это отдельный вспомогательный метод, а не общая схема Ford–Sidi.
Если все окна вырождены, C++ бросает исключение, Python возвращает последнюю
исходную оценку; такой fallback не доказывает сходимость.

## Проверки

Anderson сравнивается с независимым решением рациональной системы нормальных
уравнений при lambda>0 и KKT-системы минимальной нормы при lambda=0.
Ford–Sidi — с точным решением системы для базиса ошибки, без рекурсии исключения.
Проверены обе арифметики, разные памяти, beta, регуляризации, пять остатков,
начала окна и порядки, положительная/отрицательная амплитуда геометрической ошибки,
нулевой ранг, обратный поиск до нулевого окна, размеры и некорректные параметры.

Добавлено 432 сравнения C++/Python; C++ отдельно проверяет комплексный Anderson
и Ford–Sidi порядка 20 при 400 битах MPFR (согласие с формулой Левина до 1e-70).
Для каждого метода проверены запуск по конфигурации и сохранение результата.
C++ target `shanks`, CTest и ASan/UBSan проверяются вместе с предыдущими этапами.
GUI-тесты исключены; предупреждения multiprocessing fork остаются прежними.

Новая выгрузка: `mathematical_regressions --seventh-algorithm-values`.
Воспроизведение общего прогона — по mathematical-verification.md.
Изменения локальные, без коммитов и push.

Дополнительно исправлено полиморфное владение C++: в `series_acceleration`
и `remainders::transform_base` добавлены виртуальные деструкторы. Фабрики и
стратегии владеют производными объектами через базовые unique_ptr; прежде
удаление через них имело неопределённое поведение. Добавлены статические
проверки и регрессия с контролем фактического вызова обоих деструкторов.
Изменение требует пересборки C++-клиентов из-за изменения виртуальных таблиц.
