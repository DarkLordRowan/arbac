# Третий этап: основной каталог рядов и проверка рекурсий

В обеих рабочих ветках `Magister` добавлены **50 рядов** и два ускорителя:
`overholt`, `lubkin_w`. Всего в Python: **99 синтетических рядов и 11 ускорителей**.
Из исходных 109 C++-позиций проверенные Python-аналоги имеют **98**.
Отдельный базовый `log1p` объясняет разницу между этими числами.

## Что перенесено

- 20 масштабированных рациональных/быстрых тестовых рядов, включая π, π/4,
  π³/32, ζ(2)-1, логарифмические константы и телескопические суммы.
- J_alpha Бесселя, нижняя неполная gamma, полные эллиптические K/E,
  W0 Ламберта, ряд по полиномам Лежандра и ряд Дирихле для φ(n).
- Девять дополнительных элементарных разложений, включая log(cos x),
  log(sin x/x), разложения около x=1 и рациональные функции.
- 14 рядов Фурье/частичных дробей с явно заданными ветвями и концами интервала.

Сохранены id и индексация C++. Эллиптический аргумент x означает **модуль k**;
backend-функциям передаётся параметр m=k². Для вещественных J_alpha используются
x>=0, alpha>=0; для нижней gamma — x>=0, alpha>0. Области сходимости явно
заданы и не претендуют на максимальность для каждого особого набора параметров.
У log(sin x/x) и πx*coth(πx)-1 предусмотрены съёмные особенности при x=0.
Два исторических id для log(cos x) сохранены как разные записи каталога.

Рекурсивные процессы Overholt и W проверены на точной рациональной арифметике.
Для Overholt уточнён расход данных: при k>0 нужны n+k+2 членов, при k=0 — n+1.
Для W нужны n+3k+1 членов. Вырожденные шаги используют доступную оценку;
такой fallback не доказывает сходимость.

## Исправления C++ и backend

1. В `three_minus_pi` приведение π к int делало заявленную сумму нулевой.
   Теперь π вычисляется в типе значения; отдельно проверены 200 бит MPFR.
2. В 18 рациональных генераторах произведения индексов выполняются после
   преобразования в тип значения. Сохранение коэффициентов проверено при n=10⁶;
   старое unsigned32-переполнение искажало даже знаменатели на умеренных индексах.
3. В `minus_3_div_4_or_x_minus_3_div_4` исправлены косинусные гармоники:
   они должны быть нечётными, тогда как синусная часть использует все гармоники.
4. В `ln_sinx_minus_ln_x` устранён NaN при нуле, включены отрицательные
   вещественные аргументы внутри |x|<π и исправлена арифметика индексов.
5. В Левине убрано лишнее смещение beta на единицу; рекурсивные формы
   Левина и Sidi-S теперь реализуют конечные разности тех же весов,
   что и прямые формы. Весовой код общий, биномиальные коэффициенты не
   вычисляются в ограниченном типе индекса.
6. У Weniger исправлены недостающий член an при расчёте required_input
   и обращение к пустым данным до проверки размера.
7. У Overholt исправлены сигнатура виртуального how_much для разных типов
   индекса и завышенный расход данных. У W чтение Sn[0] перенесено за валидацию.
8. Добавлены проверки вещественных аргументов J_alpha и нижней gamma;
   запрещены конфигурации, в которых исходная реализация делила на ноль
   или обращалась к функции GSL вне поддержанной области.
9. В Arb большие Python-int передаются напрямую, без десятичной строки.
   Это устраняет лимит Python на длину такой строки у больших биномиальных
   коэффициентов. Проверены коэффициенты при n=10000.

Sidi-S — тот же факториальный S-трансформ, который в Python представлен
плагином `weniger`; отдельного дублирующего плагина не добавлено.
Проверены пять оценок остатка, beta=1 и 2.5, несколько окон и порядков.
Для Левина/Sidi-S дополнительно проверен порядок 40 при 200 битах MPFR,
чтобы обнаруживать переполнение биномиальных коэффициентов.

## Независимые проверки

- **1796 Python-тестов прошли** на mpmath и Arb; GUI не проверялся.
- **776 коэффициентов 97 рядов** сопоставлены с C++; ряд ζ проверен отдельно.
- **315 значений ускорителей** сопоставлены с C++.
- Коэффициенты Фурье получаются численным интегрированием заявленных
  кусочных функций по определению коэффициентов, а не копированием формул генератора.
- Рациональные суммы проверены независимым mpmath.nsum и точными конечными
  телескопическими тождествами. Для медленных рядов используются оценки хвоста.
- Для специальных функций проверены коэффициенты, независимые закрытые формы,
  области определения, нормировки и соглашения об аргументах.
- CTest и проверки с санитайзерами дополняют численные тесты.

Запуск из Linux/WSL:

```sh
cd shanks-university
cmake -S backend/core -B /tmp/shanks-build -DBUILD_TESTING=ON
cmake --build /tmp/shanks-build --target mathematical_regressions catalogue_probe -j2
ctest --test-dir /tmp/shanks-build --output-on-failure
cd ../arbac
SHANKS_CPP_REGRESSIONS=/tmp/shanks-build/mathematical_regressions \
SHANKS_CPP_CATALOGUE=/tmp/shanks-build/catalogue_probe \
python -m pytest --ignore=tests/gui
```

Без переменных окружения соответствующие межъязыковые тесты явно пропускаются.
Использование внешних файлов с другой версией исходников не обеспечивает
согласованной проверки: сначала нужно собрать оба C++-бинарника.

## Оставшиеся 11 позиций каталога

- Семь последовательностей Румпа: для них требуется сохранить семантику
  последовательности, отличную от суммирования её значений как членов ряда.
- `natural_series`: обычная сумма расходится; -1/12 является регуляризованным
  значением. Его нельзя переносить как эталон обычной сходимости.
- `integral1`: конечная квадратура с логарифмической особенностью и пропущенным
  краевым интервалом. Нужны корректная трактовка и независимая проверка квадратуры.
- `minus_one_n_fact_n_in_n` и `minus_one_ned_in_n`: get_sum содержит только
  восьмизначные десятичные приближения. Для тестов высокой точности нужен
  независимый эталон, например интегральное представление.

Также остаются 12 семейств/вариантов C++-ускорителей из таблицы покрытия.
Наличие положительного результата численного пробника не переводит их
автоматически в статус проверенных.
