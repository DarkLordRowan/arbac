# Завершение проверки каталога и дополнительные инструменты

Изменения этого этапа оставлены незакоммиченными по указанию пользователя.

## Обязательные задачи 1.1–3

Каталог C++ содержит 109 источников; у каждого есть Python-перенос и независимый
математический эталон. В arbac проверены 110 синтетических источников, источник
из файла и все 23 зарегистрированных семейства ускорителей. Проверяются формулы,
индексация, расход входных значений, эталонные суммы, особые точки и ошибки.
Отдельно проверены mpmath и Arb, MPFR и комплексные C++-инстанцирования.
Границы областей применимости и различие обычной суммы и регуляризации
описаны в предыдущих отчётах. Тесты конечных траекторий не являются
доказательством сходимости при произвольных параметрах.

Закрыты оставшиеся реализованные числители rho:

- `numerator="classic"`: разности узлов; поддерживается также Python-сетка
  `(n+grid_shift)**grid_power` из этапа 9.
- `numerator="generalized"`: числитель `column-1-gamma`. Это вариант Осалды
  с alpha=-gamma; теорема ускорения требует alpha>0. Сверка:
  [Osada (1990)](https://doi.org/10.1137/0727012),
  [Chang et al. (2019)](https://arxiv.org/pdf/1903.10198), (2.14)–(2.15).
- `numerator="gamma_rho"`: историческая алгебраическая формула C++
  `-gamma+column/(2*rho)+(column mod 2)`. Сохранена совместимость;
  она не объявляется автоматической оценкой показателя сходимости.
  Прежние комментарии ошибочно описывали целочисленное деление.

Для двух параметризованных вариантов нельзя одновременно задавать собственную
сетку. gamma должен быть конечным; делитель rho — конечным и ненулевым.
Исправлены C++ проверки и unsigned underflow в generalized при column=0.
Тесты используют Fraction с точными рациональными входами, независимую
замкнутую формулу первого чётного столбца, 144 значения C++/Python,
а также ускорение нецелых степенных моделей alpha=0.5,1.5,2.5.

W^(m) в прежних заметках обозначал возможное расширение по литературе.
Существующие C++ Ford–Sidi 2/3 не реализуют полное семейство W^(m):
их фактические алгоритмы перенесены и проверены под точными названиями
aitken_backtracking и ford_sidi (Levin basis). Изобретать дополнительные
варианты, отсутствующие в исходном каталоге, для выполнения переноса не требуется.

## Python runner исходного репозитория

Исправлены обнаруженные ошибки:

- Сериализация результатов и аргументов больше не округляет через float:
  сохраняются различия 1.000…001 и 1.000…002, значения 1e-500 и 1e500.
- Размер входа раньше оценивался как n+m+5, хотя Lubkin требует n+3m+1.
  Теперь предусмотрен запас для всех текущих шаблонов и оценок остатка;
  пустые и неверные сетки индексов отклоняются.
- Некорректная ячейка CSV больше не превращается молча в ноль.
  CArb CSV не проходит через binary64.
- Сериализатор и приведение FLong работают и в сборке без profiling, где
  отдельные классы F32/F64/FLong отсутствуют. В этой конфигурации граница
  Python/native для обычных типов по-прежнему использует Python float;
  для десятичных входов с высокой точностью следует выбирать Arb/CArb.
- Демонстрационный test_algos использует общий механизм приведения точности.

Новые тесты запускаются отдельно от исторических интерактивных plot-скриптов:
`PYTHONPATH=backend/runner/src python -m pytest backend/runner/tests` — 28 passed.
Они используют реальные существующие bindings; математические исправления
заголовков проверяются свежими нативными C++-регрессиями.

## GUI и дополнительная функциональность из TypeScript

Исправлена потеря run_id/output при from_config → to_config → Save/Run.
Сохраняются также дополнительные настройки верхнего уровня. Run больше
не подменяет каталог текущей конфигурации предыдущим last_output_root.
Добавлены регрессии на сохранённый файл и фактический каталог результатов.
GUI проверяется offscreen, включая настоящий RunWorker: 73 passed.

`arbacc.analysis.experiment` принимает JSON-схему веб-эксперимента:
seriesList, accelList, seriesAccelList. Реализованы разреженная матрица пар,
фильтрация осей, диагностика ошибок/сходимости, анализ profiling из
profilingUtils.ts, рейтинг и JSON/CSV-экспорт. Точные целочисленные счётчики
и числа backend не преобразуются в binary64. Пропущенная пара не становится
нулевой ошибкой; дубликаты и неизвестные ссылки отклоняются.

Рейтинг имеет явно заданную метрику: средняя минимальная абсолютная ошибка
из известных траекторий, плотные ранги при равенстве. Это дополнительный
Python-рейтинг, не копия всех составных весов браузера. Сравнивать разные
масштабы следует после фильтрации матрицы. React-интерфейс и браузерное
оформление не переносились: у arbac уже есть собственный Python GUI.

```bash
python -m arbacc.cli experiment-report experiment.json report.json --dps 100 --epsilon 1e-80
python -m arbacc.cli experiment-report experiment.json report.csv --backend arb --dps 100
```

```bash
cmake -S ../shanks-university/backend/core -B /tmp/shanks-cmake-verify -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/shanks-cmake-verify --target shanks mathematical_regressions catalogue_probe -j2
ctest --test-dir /tmp/shanks-cmake-verify --output-on-failure
python tools/build_qelg_reference.py --output /tmp/shanks-qelg-verified
QT_QPA_PLATFORM=offscreen \
SHANKS_CPP_REGRESSIONS=/tmp/shanks-cmake-verify/mathematical_regressions \
SHANKS_CPP_CATALOGUE=/tmp/shanks-cmake-verify/catalogue_probe \
SHANKS_QELG_REFERENCE=/tmp/shanks-qelg-verified python -m pytest tests -q
```

Установлены зависимости requirements.txt, python-flint и pytest-qt.
C++ CTest 1/1; ASan/UBSan математических регрессий — без ошибок.
Предупреждения Python относятся к существующему fork из многопоточного Qt-процесса.
Полный результат последнего прогона указан в основном отчёте.
