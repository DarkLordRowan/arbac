# Продолжение: F, H и pJ Хомайера

В `Magister` добавлены `homeier_f`, `homeier_h`, `homeier_pj`; теперь в Python
17 ускорителей. Все 109 источников C++ остаются покрыты. Остаются 6 семейств:
Anderson, Chang–Wynn, Ford–Sidi 2/3, J и Wynn epsilon 3. Статус относится к
семействам заголовков; не все дополнительные варианты уже проверенных методов
(например, числители rho) перенесены.

## Формулы и исправления

Основной источник — [Homeier, Scalar Levin-Type Sequence Transformations](https://arxiv.org/pdf/math/0005209):
F — (140)/(148), H — (155)/(157), pJ — (98)/(105)/(107).

F использует сетку `x_i=grid_shift+grid_scale*i**grid_power`. В Python сдвиг >1,
масштаб >0, степень — положительное целое; все вещественные параметры конечны.
В C++ сохранён callback произвольной сетки; для упорядоченных числовых типов
проверяется её возрастание и x>1, для всех — конечность и ненулевые делители.
Исправлены переполнение индекса в дефолтной сетке, нулевой порядок и тихое
сохранение старых ячеек при ошибках рекурсии.

H требует окно из **2k+1** частичных сумм. Раньше C++ выделял его, но заполнял
только k+1 значений, а затем читал оставшиеся нули; неверны были и границы
внутреннего цикла. Исправлены заполнение и сокращение окна на два значения
за уровень, параметры beta>0 и cos(alpha)≠±1. Дефолтный угол pi/4 вычисляется
в заданной точности; в Python можно задать строку `alpha="pi/4"` или число.

pJ: исправлены коэффициенты Psi, перепутанные числитель/знаменатель, знак
сдвига и использование уровня k вместо k-1. Единая форма произведения
покрывает p=1,2 и остальные положительные целые без деления на p-2.

Для всех методов поддержаны `next`, `t`, `u`, `v`, `v_shift`.
В C++ u-вариант раньше использовал нулевой сдвиг, вызывая деление на ноль при
n=0; теперь применяется (i+beta)*a_i. Для F добавлен необязательный третий
параметр конструктора beta=1. Параметр beta оценки остатка F отделён от
сдвига сетки. Python по умолчанию использует next, C++ сохраняет прежний u.

При нулевом порядке ускорители возвращают s_n без чтения an. Размеры проверяются
до первого доступа. C++ выбрасывает исключение при сингулярном результате;
Python сохраняет доступное исходное значение. Это не доказательство сходимости.
Python поддерживает вещественные параметры; C++ сохраняет комплексные типы.

## Независимая проверка

F сравнивается с барицентрической формой разделённых разностей на линейной
и квадратичной сетках. H — с коэффициентами многочлена
`(z²-2 cos(alpha) z+1)^k`, а также с точной моделью осциллирующей ошибки.
pJ — с исходной схемой обобщённых разностей Delta/delta, не использующей Psi.
Эталоны вычисляются Fraction или отдельным контекстом mpmath.

Проверяются оба backend, пять остатков, разные beta, порядки, начала окна,
параметры p=1/2/3/5, частоты, константы, нулевой порядок и некорректные входы.
Добавлены 960 сравнений с реальными заголовками C++, проверки MPFR 200 бит:
F порядка 20, pJ порядка 12, H порядка 3. Дефолтная частота H проверяется
при 120 десятичных знаках. Конфигурация, исполнение и сохранение результатов
протестированы для каждого нового метода с mpmath и Arb.

C++ target `shanks` собран; CTest 1/1; ASan/UBSan — без ошибок.
GUI-тесты исключены, остаются прежние предупреждения multiprocessing fork.
Воспроизведение — по mathematical-verification.md. Новая C++ выгрузка:
`mathematical_regressions --sixth-algorithm-values`.
