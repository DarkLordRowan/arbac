# Arbac Magister — ручная публикация полного обновления

Эта папка содержит **полную обновлённую библиотеку**, а не дополнительный патч.

Включены:
- `arbacc/` — математическое ядро, источники последовательностей и все зарегистрированные ускорители;
- `arbac_research/` — пакетные JSON-эксперименты, Parquet/ZSTD, независимый GUI и метрики;
- `gui/` — существующий интерфейс Arbac;
- `tests/` и `research_tests/` — тесты алгоритмов, точности, библиографии, профилирования, хранения;
- `docs/` — литература, протоколы проверки, заметки к статье и важные ограничения;
- `examples/` — конфигурации, включая пример исследования;
- `requirements*.txt`, `tools/`, диагностические и PowerShell-скрипты.

## Ручной коммит без команд из этого архива

1. Сделайте локальную резервную копию существующего репозитория.
2. Откройте свой локальный Git-репозиторий `arbac`, выберите ветку **`Magister`** с большой `M`.
3. Перенесите **содержимое** этой папки `arbac-Magister` **в корень репозитория** (рядом с существующим `arbacc/` и `.gitignore`), разрешив замену одноимённых файлов. Не удаляйте каталог `.git`.
4. Через GitHub Desktop либо другой графический Git-клиент посмотрите все изменения, не добавляйте `out/`, Parquet и временные результаты. Выполните commit и push в **`Magister`**, без переписывания истории.
5. Проверьте, что в GitHub появились `arbac_research/`, `research_tests/`, `arbacc/accelerators/levin_sidi_s.py` и `docs/ALGORITHM_LITERATURE.md`.

### Проверка и ограничения

- По предыдущему запуску пользователя на Windows: 4013 тестов ядра прошли, 61 пропущен; 35 тестов Research прошли.
- В контейнере при сборке архива прошёл набор из 171 теста; 1 пропуск связан с дополнительной зависимостью.
- Математические вычисления алгоритмов здесь не переписывались; библиографические сведения добавлены как метаданные.
- `levin_sidi_s` проверен на рациональной факториальной модели и по независимому `mpmath`, но историческую атрибуцию всё ещё следует формально проверить по первоисточнику. Не считать автоматически независимым от Weniger S.
- Многогигабайтные результаты Stage C/E не входят в архив. Для статьи их придётся хранить и анализировать отдельно.
- На GitHub **ничего не отправлено** из данной сборки.
