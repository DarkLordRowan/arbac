# Что измеряет новая версия v3

| Показатель | Источник | Что означает | Ограничения |
|---|---|---|---|
| `gain_best_orders` | наш тезис | `log10(|S_m-S| / |A_m-S|)` для лучшего (по известному пределу) шага | ретроспективный выбор шага, необходима база и эталон |
| `gain_last_orders` | Arbac Research | то же на последнем корректном шаге | не обязательно лучший результат |
| `cpp_orders_gain_vs_series_min` | идея из C++ веб-рейтинга | сравнение двух минимумов ошибок на разных траекториях | бюджеты могут различаться; соглашение при нулевых ошибках особое |
| `c1`, `c5` | наш тезис | сокращение ошибки минимум в 10 / 10^5 раз, по уникальным тестовым последовательностям | в группах выбор параметров `ORACLE`, а не честный CV |
| `epsilon_saved_terms` | C++ и Arbac Research | число членов исходной последовательности, сэкономленных до ε | определено, только когда обе траектории достигли ε |
| `sign_changes`, `error_monotonicity` | C++ и Arbac Research | поведение траектории приближений | знаки имеют смысл лишь для вещественных последовательностей |
| `op_add`, `op_mul`, `op_div`, `op_neg`, `op_special` | **новая** v3 | вызовы Python API backend *внутри* `accelerator.step` | НЕ эквивалентно счётчикам C++ и НЕ полная арифметическая сложность |
| `op_total` | **новая** v3 | сумма пяти категорий вызовов | только при явном включении профиля; прямые `mpmath`/Arb вызовы в обход backend не учитываются |
| `step_elapsed_ms_sum` | **новая** v3 | сумма времени корректных вызовов `accelerator.step` | профилирование может замедлять работу; не сравнивать разные режимы |
| `n_events`/`n_step_failures` | **новая** v3 | сохранённые события `step_failure` / `runner_stop` | v1/v2 не имели этих данных |
| `division_zero_first_n` | **новая** v3 | число исходных членов на зафиксированном исключении деления на ноль | отсутствие события ≠ математическая гарантия отсутствия проблем |

`NULL` означает отсутствие данных, а не «0 операций». В обычных расчетах
профилирование отключено; результаты и их время не должны искажаться
счётчиками операций. 

### Зачем отдельно считать операции

В C++ проекте собирались свои счётчики `add`, `mul`, `div`, `special`, иногда
вместе с составной эвристической оценкой сложности. Новая версия собирает
вызываемые методы Python `ctx.backend`; это **другой уровень** наблюдения.
Для публикации не следует напрямую сравнивать абсолютные счётчики между C++ и
Python без предварительной калибровки на одинаковых элементарных операциях.

### Что ещё не включено

- События фильтров и их срабатывания, поскольку текущий независимый runner
  не исполняет postprocess/envelope этапы.
- CPU time / memory peak / количество битовых операций `mpmath` и Arb.
- Верификация всех поздних методов из локальных архивов и перенос их в
  базовую библиотеку — для этого нужен исходный код последней версии.
